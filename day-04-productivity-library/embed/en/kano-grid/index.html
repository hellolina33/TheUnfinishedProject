Kano Model

Separates features people expect from features that delight them, so you do not over-invest in basics.

Expected result

A table of features classified by customer response.

Fictional worked case

An online shop wants to learn whether tracking matters as much to buyers as secure payment.

Buyers expect secure checkout and are unhappy without it, suggesting a basic need. They can tolerate no live tracking, but like having it, suggesting an attractive feature.

A secure checkout meets a basic expectation. Live tracking can delight users who did not expect it.

Steps

  1. List the features. For each one, ask: how would I feel if it were present? If it were missing?
  2. Classify each as must-have, performance, delighter, or indifferent.
  3. Fund the must-haves first, then the delighters.

Review

Test both questions with buyers and compare the most frequent classification for each feature.

Limitations

Ask both the presence and absence questions without telling respondents which answer you expect.

Noriaki Kano and colleagues (1984).
